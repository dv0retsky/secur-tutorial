# Практическое занятие №16: Итоговая защита курсовой работы по дисциплине «Методы защиты информации»

## 1. Подведение итогов

Перед началом защиты проверяется комплектность материалов.

Необходимо представить:

- пояснительную записку;
- презентацию;
- исходный код;
- репозиторий;
- инструкцию по запуску;
- демонстрационные данные;
- результаты тестирования.

Также проверяется выполнение замечаний, полученных на предзащите.

## 2. Структура доклада

Рекомендуемая последовательность:

```text
1. Тема и актуальность
2. Цель и задачи
3. Описание защищаемой системы
4. Защищаемые ресурсы
5. Основные угрозы
6. Реализованные методы защиты
7. Архитектура
8. Результаты тестирования
9. Итог
```

Основное внимание должно уделяться инженерным решениям и их обоснованию.

## 3. Демонстрация программного продукта

После доклада необходимо показать работу программы.

Минимальный сценарий:

```text
запуск
↓
обычная работа
↓
попытка нарушения требования
↓
срабатывание защиты
↓
подтверждение результата
```

Пример:

```text
Пользователь входит в систему
↓
Открывает собственный объект
↓
Пытается обратиться к чужому объекту
↓
Система запрещает доступ
↓
Событие фиксируется в журнале
```

## 4. Что необходимо объяснить на защите

Студент должен быть готов объяснить:

- почему выбрана эта архитектура;
- почему рассматриваются именно эти угрозы;
- каким образом каждая угроза связана с защитным механизмом;
- почему выбран конкретный алгоритм или библиотека;
- какие ограничения имеет реализация;
- как проводилось тестирование;
- какие результаты подтверждают работу защиты.

## 5. Типичные вопросы

1. Чем угроза отличается от уязвимости?
2. Где проходит граница доверия?
3. Что произойдёт при компрометации БД?
4. Почему пароль нельзя хранить в открытом виде?
5. Где выполняется авторизация?
6. Что мешает пользователю изменить параметры запроса?
7. Что будет при отключении одного из механизмов защиты?
8. Какие атаки проект не рассматривает?
9. Как можно развить работу?
10. Каким тестом подтверждается конкретное требование?

## 6. Критерии итоговой оценки

| Критерий | Доля |
|---|---:|
| Постановка задачи и актуальность | 10% |
| Анализ угроз и требований | 15% |
| Обоснование методов защиты | 15% |
| Программная реализация | 25% |
| Экспериментальная проверка | 15% |
| Оформление пояснительной записки | 10% |
| Доклад, демонстрация и ответы | 10% |
| **Итого** | **100%** |

## 7. Признаки сильной курсовой работы

Сильная работа отличается целостностью:

```text
защищаемый ресурс
↓
угроза
↓
требование
↓
метод защиты
↓
реализация
↓
тест
↓
результат
```

Дополнительно проект должен:

- запускаться по инструкции;
- не содержать реальных секретов;
- использовать обоснованные методы;
- демонстрировать негативные сценарии;
- содержать понятную архитектуру;
- честно описывать ограничения.

## 8. Что снижает оценку

К существенным недостаткам относятся:

- отсутствие работающей программной части;
- отсутствие модели угроз;
- отсутствие связи между угрозами и реализованной защитой;
- отсутствие тестирования;
- отсутствие инструкции по запуску;
- невозможность воспроизвести проект;
- использование небезопасных решений без объяснения;
- несоответствие текста фактической реализации.

## 9. Финальная проверка

```text
[ ] проект запускается
[ ] тестовые данные подготовлены
[ ] презентация открывается
[ ] репозиторий доступен
[ ] README актуален
[ ] демонстрационный сценарий проверен
[ ] замечания устранены
[ ] секреты удалены из репозитория
[ ] результаты тестов сохранены
[ ] пояснительная записка готова
```

## 10. После защиты

После выступления преподаватель фиксирует результаты защиты и итоговые баллы за курсовую работу.

При необходимости могут быть сформулированы отдельные замечания по окончательной версии материалов.
