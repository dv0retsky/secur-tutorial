# Практическое занятие №11: Aнализ предметной области и описание защищаемой системы

## ✏️ Описание программируемой системы

Описание рекомендуется строить от общего к частному. Сначала указывается назначение системы, затем категории пользователей, основные функции, входные и выходные данные, хранилища и предполагаемая среда эксплуатации.

Пример:

> Разрабатываемая система представляет собой веб-приложение для хранения пользовательских документов. Пользователь проходит аутентификацию, после чего получает доступ только к принадлежащим ему файлам. Приложение обеспечивает загрузку, просмотр, удаление и защищённое хранение документов. Для административной роли предусмотрены функции управления учётными записями и просмотра журнала событий безопасности.

Необходимо указать, какие данные поступают извне и должны считаться недоверенными до выполнения проверки на стороне системы.

## ✏️ Защищаемые информационные ресурсы

**Информационный ресурс** — данные, программные функции или вычислительные возможности, представляющие ценность для пользователя или владельца системы.

К ресурсам могут относиться учётные записи, пароли, сессионные идентификаторы, документы, база данных, административные функции, журналы событий, токены и криптографические ключи.

| 4 |  |  |  |
| 5 |  |  |  |

Для каждого ресурса следует определить, что необходимо обеспечить: конфиденциальность, целостность, доступность, подлинность или контролируемость доступа.

## ✏️ Пользователи и роли

Если система предполагает несколько категорий пользователей, необходимо определить их права заранее.

Пример:

```text
Гость
  ↓
Регистрация / вход
  ↓
Пользователь
  ↓
Работа только со своими данными

Администратор
  ↓
Управление пользователями
  ↓
Просмотр журналов безопасности
```

Удобно использовать таблицу:

| Роль | Разрешённые действия | Запрещённые действия |
|---|---|---|
| Гость |  |  |
| Пользователь |  |  |
| Администратор |  |  |

## ✏️ Основные сценарии работы

Сценарий показывает последовательность действий пользователя и системы.

Например:

```text
Пользователь → вводит логин и пароль
Система → проверяет учётные данные
Система → создаёт пользовательскую сессию
Пользователь → получает доступ к разрешённым функциям
```

Для курсовой работы достаточно выделить 3–5 основных сценариев. На следующем занятии эти сценарии будут использованы для поиска потенциальных угроз.

## ✏️ Обзор существующих решений

Необходимо рассмотреть не менее трёх аналогичных продуктов, библиотек, сервисов или архитектурных подходов.

Обзор должен быть сравнительным, а не описательным.

| Решение | Назначение | Механизмы защиты | Преимущества | Ограничения |
|---|---|---|---|---|
| Решение 1 |  |  |  |  |
| Решение 2 |  |  |  |  |
| Решение 3 |  |  |  |  |

После таблицы необходимо сформулировать вывод: какие подходы из существующих решений будут использованы в собственной работе и какие ограничения учитываются.

## ✏️ Список использованных источников

Источники следует собирать одновременно с выполнением аналитического раздела. Предпочтение необходимо отдавать официальной документации, стандартам, научной и учебной литературе, а также документации используемых библиотек.

На этой неделе рекомендуется сформировать предварительный список из **8–10 источников**.

## ✏️ Практическая работа на занятии

На занятии необходимо:

1. представить утверждённую тему;
2. подготовить описание системы объёмом 1–2 страницы;
3. выделить защищаемые ресурсы;
4. определить пользователей и роли;
5. сформировать основные сценарии работы;
6. сравнить не менее трёх существующих решений;
7. подготовить предварительную архитектурную схему.
