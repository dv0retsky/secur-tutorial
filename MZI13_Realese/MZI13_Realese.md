# Практическое занятие №13: Реализация требований и функциональное тестирование

## 1. Реализация требований к системе

Разработка должна опираться на перечень требований.

| ID | Требование | Компонент | Статус |
|---|---|---|---|
| FR-01 |  |  | Не начато / В работе / Готово |
| SEC-01 |  |  |  |
| SEC-02 |  |  |  |

Это позволяет проверить, что требования из пояснительной записки действительно отражены в коде.

## 2. Реализация механизмов защиты

Для каждого механизма необходимо объяснить:

1. какую угрозу он нейтрализует;
2. где применяется;
3. какой алгоритм или библиотека используется;
4. какие параметры выбраны;
5. какие ограничения остаются.

Не рекомендуется реализовывать криптографические алгоритмы самостоятельно, если создание собственного алгоритма не является предметом курсовой работы.

## 3. Безопасность конфигурации

В репозитории не должны храниться реальные пароли, токены, API-ключи, секреты сессий и приватные ключи.

Пример:

```python
import os

SECRET_KEY = os.environ["SECRET_KEY"]
DATABASE_URL = os.environ["DATABASE_URL"]
```

## 4. Функциональное тестирование программного продукта

**Функциональное тестирование** проверяет, выполняет ли система заявленные пользовательские функции.

| № | Действие | Ожидаемый результат |
|---:|---|---|
| 1 | Регистрация пользователя | Учётная запись создаётся |
| 2 | Вход с корректными данными | Пользователь авторизован |
| 3 | Вход с неверным паролем | Доступ не предоставляется |
| 4 | Создание объекта | Объект сохраняется |
| 5 | Удаление объекта | Объект удаляется |
| 6 | Выход | Сессия завершается |

## 5. Негативные сценарии

Следует проверить пустые поля, слишком длинный ввод, неверные типы данных, отсутствие прав доступа, несуществующие идентификаторы и обращение к защищённым функциям без аутентификации.

Система не должна возвращать пользователю внутренние трассировки и служебные секреты.

## 6. Инструкция по эксплуатации системы

К проекту необходимо подготовить `README.md`.

Рекомендуемая структура:

```markdown
# Название проекта

## Назначение
## Требования
## Установка
## Настройка переменных окружения
## Инициализация базы данных
## Запуск
## Тестовые учётные записи
## Реализованные механизмы защиты
```

## 7. Воспроизводимость проекта

Перед сдачей следует выполнить тест на «чистой» среде:

```text
клонирование репозитория
→
установка зависимостей
→
настройка конфигурации
→
инициализация БД
→
запуск
→
проверка основных сценариев
```

## 8. Демонстрация программного продукта

На занятии проводится промежуточная демонстрация.

Необходимо показать:

1. запуск проекта;
2. основной пользовательский сценарий;
3. ключевые функции;
4. работу хотя бы одного механизма защиты;
5. структуру репозитория;
6. прогресс по требованиям.

## 9. Что нужно сдать на этой учебной неделе

- рабочий прототип;
- основные функции;
- ключевые механизмы защиты;
- таблицу статуса требований;
- результаты функционального тестирования;
- первую версию `README.md`;
- обновлённую пояснительную записку;
- репозиторий проекта.
