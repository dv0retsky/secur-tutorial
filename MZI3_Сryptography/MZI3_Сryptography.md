# Практическое занятие №3: Основы криптографии

# 1. Что такое криптография

**Криптография** — область науки и техники, изучающая методы математического преобразования информации для обеспечения её защищённости при хранении, обработке и передаче.

Исторически криптография прежде всего ассоциировалась с сокрытием содержания сообщения. Современная криптография решает значительно более широкий круг задач. С её помощью обеспечиваются конфиденциальность данных, контроль их целостности, подтверждение подлинности участников обмена и проверка авторства электронных сообщений.

Криптографические механизмы используются практически во всех современных информационных системах. Когда пользователь открывает сайт по HTTPS, подключается к серверу по SSH, подтверждает электронный документ цифровой подписью, вводит пароль в защищённом сервисе или устанавливает обновление операционной системы, в этих процессах в той или иной форме участвуют криптографические алгоритмы.

Важно понимать, что криптография сама по себе не делает информационную систему полностью безопасной. Даже стойкий алгоритм может быть скомпрометирован неправильной реализацией, слабым генератором случайных чисел, утечкой ключа, ошибочной конфигурацией или действиями пользователя. Поэтому криптографические методы рассматриваются как один из уровней общей системы защиты информации.

---

# 2. Основные понятия криптографии

**Открытый текст (plaintext)** — исходные данные до криптографического преобразования.

**Шифротекст (ciphertext)** — результат шифрования, который не должен раскрывать содержание исходных данных без знания необходимого ключа.

**Шифрование (encryption)** — преобразование открытого текста в шифротекст.

**Расшифрование (decryption)** — обратное преобразование шифротекста в открытый текст при наличии требуемого ключа.

**Криптографический алгоритм** — формально определённый алгоритм, выполняющий криптографическое преобразование данных.

**Ключ** — параметр криптографического алгоритма, определяющий конкретный результат преобразования.

Упрощённо процесс симметричного шифрования можно записать как:

```text
Открытый текст
      |
      |  ключ K
      v
 [Шифрование]
      |
      v
  Шифротекст
      |
      |  ключ K
      v
[Расшифрование]
      |
      v
Открытый текст
```

В математической записи:

```text
C = E_K(P)
P = D_K(C)
```

где `P` — открытый текст, `C` — шифротекст, `E` — функция шифрования, `D` — функция расшифрования, `K` — криптографический ключ.

Современная криптография исходит из того, что безопасность системы должна определяться секретностью ключа, а не секретностью самого алгоритма. Этот подход соответствует **принципу Керкгоффса**: криптографическая система должна оставаться безопасной даже в том случае, если злоумышленнику известны все детали алгоритма, кроме секретного ключа.

Именно поэтому алгоритмы AES, RSA, SHA-2 и другие широко публикуются и подробно исследуются. Открытость алгоритма позволяет криптографическому сообществу анализировать его свойства, а секретным остаётся конкретный ключ.

# 3. Какие задачи решает криптография

## 3.1. Конфиденциальность

**Конфиденциальность** предполагает, что содержание данных доступно только тем субъектам, которым предоставлено соответствующее право.

Шифрование является одним из основных средств обеспечения конфиденциальности. Если злоумышленник перехватит корректно зашифрованный трафик, он получит шифротекст, но без ключа не должен иметь практической возможности восстановить исходное сообщение.

## 3.2. Целостность

Криптографические механизмы позволяют обнаруживать несанкционированное изменение информации.

Для этого применяются хеш-функции, коды аутентификации сообщений и цифровые подписи. Если защищаемые данные были изменены, проверка должна показать несоответствие.

При этом обычный хеш сам по себе не всегда обеспечивает защиту от активного злоумышленника. Если атакующий может заменить и файл, и опубликованный рядом хеш, проверка становится бессмысленной. Для подтверждения подлинности источника применяются дополнительные механизмы — например, цифровая подпись или HMAC.

## 3.3. Аутентификация

**Аутентификация** — проверка того, действительно ли субъект или объект является тем, за кого себя выдаёт.

Криптография используется для подтверждения владения секретным ключом, проверки сертификатов, аутентификации сетевых узлов и пользователей.

## 3.4. Неотказуемость

**Неотказуемость** в прикладном контексте означает наличие криптографических и организационных механизмов, позволяющих подтвердить факт формирования определённой электронной подписи владельцем соответствующего закрытого ключа.

Цифровая подпись является важным элементом подобных систем, однако юридическая неотказуемость определяется не одной математической операцией. Она зависит также от правил управления ключами, идентификации владельца, защищённости средства подписи и применимого законодательства.

# 4. Криптография, кодирование и хеширование — не одно и то же

Начинающие часто смешивают три разных понятия: шифрование, кодирование и хеширование.

**Кодирование** изменяет форму представления данных, но не предполагает наличия секретного ключа. Например, Base64 преобразует бинарные данные в текстовую форму, удобную для передачи. Base64 не является шифрованием.

```text
Hello
```

после Base64-кодирования:

```text
SGVsbG8=
```

Любой пользователь может выполнить обратное декодирование.

**Шифрование** использует криптографический ключ и предназначено для ограничения доступа к содержимому.

**Хеширование** является односторонним преобразованием данных произвольной длины в значение фиксированной длины. Оно не предназначено для последующего «расшифрования».

| Операция | Обратимое преобразование | Использует секретный ключ | Типичная задача |
|---|---|---|---|
| Кодирование | Да | Нет | Представление данных |
| Шифрование | Да, при наличии ключа | Да | Конфиденциальность |
| Хеширование | Не предполагает обратного преобразования | Обычно нет | Контроль целостности |
| HMAC | Проверяется при наличии секретного ключа | Да | Целостность и аутентичность |

# 5. Краткая история криптографии

Криптография развивается на протяжении тысячелетий. На ранних этапах основная задача заключалась в том, чтобы скрыть смысл сообщения от человека, который мог перехватить письмо или военный приказ.

## 5.1. Древние методы

Одними из ранних способов сокрытия текста были перестановка и замена символов.

При **перестановке** символы сохраняются, но меняется их порядок. При **подстановке** символ исходного текста заменяется другим символом.

В Древней Спарте использовался принцип перестановочного шифрования с помощью скиталы — цилиндра определённого диаметра, вокруг которого наматывалась полоска материала. Текст читался корректно только при использовании цилиндра подходящего размера.

Эти методы были примитивными с позиции современной криптографии, но заложили два фундаментальных принципа — перестановку и замену, которые в значительно более сложном виде встречаются и в современных блочных шифрах.

## 5.2. Шифр Цезаря

**Шифр Цезаря** — классический моноалфавитный шифр подстановки, в котором каждая буква заменяется буквой, находящейся на фиксированное число позиций дальше в алфавите.

Для английского алфавита при сдвиге на 3:

```text
A -> D
B -> E
C -> F
...
X -> A
Y -> B
Z -> C
```

Пример:

```text
Открытый текст: HELLO
Сдвиг:          3
Шифротекст:     KHOOR
```

Математически:

```text
E(x) = (x + k) mod 26
D(x) = (x - k) mod 26
```

Шифр Цезаря не является безопасным: пространство ключей мало, а статистическая структура языка сохраняется.

## 5.3. Частотный анализ

Если одна буква открытого текста всегда заменяется одной и той же буквой шифротекста, сохраняются статистические особенности языка.

**Частотный анализ** использует частоты появления символов и сочетаний символов для восстановления соответствий между открытым текстом и шифротекстом.

Появление частотного анализа показало, что простой моноалфавитной подстановки недостаточно.

## 5.4. Шифр Виженера

**Шифр Виженера** — полиалфавитный шифр подстановки, в котором величина сдвига определяется символами повторяющегося ключевого слова.

Пример:

```text
Открытый текст: ATTACKATDAWN
Ключ:           LEMONLEMONLE
Шифротекст:     LXFOPVEFRNHR
```

Одна и та же буква исходного текста может превращаться в разные символы в зависимости от позиции. Это усложняет простой частотный анализ, но повторяемость ключа всё равно создаёт статистические закономерности.

## 5.5. Механические и электромеханические шифры

В XX веке получили развитие электромеханические шифровальные машины. Одним из наиболее известных примеров стала Enigma.

Её работа основывалась на системе вращающихся роторов, изменявших подстановку после каждого введённого символа. Пространство настроек было значительно больше, чем у ручных шифров.

История Enigma показывает, что стойкость зависит не только от алгоритма, но и от процедур эксплуатации, дисциплины операторов и корректного управления ключами.

# 6. Переход к современной криптографии

Появление компьютеров изменило требования к криптографическим системам. Алгоритмы должны были эффективно обрабатывать большие объёмы цифровых данных и противостоять автоматизированному криптоанализу.

В 1970-х годах сформировались фундаментальные идеи криптографии с открытым ключом. Работы Уитфилда Диффи и Мартина Хеллмана показали возможность согласования общего секрета через открытый канал. Позже появились практические криптосистемы с открытым ключом, включая RSA.

Одновременно развивались симметричные алгоритмы. DES долгое время использовался как стандарт блочного шифрования, однако его 56-битный ключ стал недостаточен против полного перебора. В дальнейшем широкое распространение получил AES.

Современные информационные системы используют сразу несколько видов криптографических примитивов:

```text
симметричное шифрование
        +
обмен ключами
        +
цифровая подпись
        +
хеш-функции
        +
генерация случайных чисел
```

# 7. Симметричная криптография

**Симметричное шифрование** — класс криптографических методов, в которых для шифрования и расшифрования используется один и тот же секретный ключ либо легко выводимые друг из друга секретные ключи.

```text
              секретный ключ K
                    |
                    v
Открытый текст -> Шифрование -> Шифротекст
                                  |
                                  v
              секретный ключ K
                    |
                    v
              Расшифрование
                    |
                    v
              Открытый текст
```

Главное преимущество симметричных алгоритмов — высокая производительность. Они хорошо подходят для шифрования больших объёмов данных.

Основная организационная проблема — безопасная передача общего секретного ключа. Если передать его по незащищённому каналу, злоумышленник сможет получить доступ к зашифрованным данным.

Поэтому симметричное шифрование часто комбинируется с асимметричными механизмами согласования ключей.

## 7.1. Примеры симметричных алгоритмов

**AES (Advanced Encryption Standard)** — современный стандарт блочного симметричного шифрования. Поддерживает ключи длиной 128, 192 и 256 бит и использует блок длиной 128 бит.

**DES** — исторически важный блочный шифр с эффективной длиной ключа 56 бит. Сегодня криптографически устарел.

**3DES** увеличивал стойкость DES многократным применением преобразования, но также относится к устаревающим схемам.

К российским симметричным стандартам относятся алгоритмы, определённые в ГОСТ 34.12-2018, включая «Кузнечик» и «Магма».

# 8. Блочные шифры

**Блочный шифр** обрабатывает данные блоками фиксированной длины.

Например, AES всегда работает с блоком 128 бит. Если сообщение длиннее одного блока, необходимо определить, как обрабатывать последовательность блоков. Эту задачу решают **режимы работы блочного шифра**.

Сам алгоритм AES и режим его применения — не одно и то же.

## 8.1. ECB

В режиме **ECB (Electronic Codebook)** каждый блок шифруется независимо:

```text
P1 -> AES_K -> C1
P2 -> AES_K -> C2
P3 -> AES_K -> C3
```

Одинаковые блоки открытого текста при одном ключе превращаются в одинаковые блоки шифротекста. Это раскрывает структуру данных, поэтому ECB не следует использовать для обычного шифрования структурированных сообщений.

## 8.2. CBC

**CBC (Cipher Block Chaining)** связывает блоки между собой. Перед шифрованием очередной блок комбинируется с предыдущим шифротекстом. Для первого блока требуется **вектор инициализации (IV)**.

CBC исторически широко применялся, однако сам по себе обеспечивает только конфиденциальность и требует отдельного механизма контроля целостности.

## 8.3. CTR

**CTR (Counter Mode)** превращает блочный шифр в механизм генерации ключевого потока. Алгоритм шифрует последовательные значения счётчика, а полученный поток объединяется с открытым текстом операцией XOR.

Крайне важно не повторять одно и то же значение nonce/счётчика с одним ключом.

## 8.4. GCM

**GCM (Galois/Counter Mode)** относится к режимам аутентифицированного шифрования и обеспечивает одновременно конфиденциальность, контроль целостности и аутентичность шифротекста.

Современные приложения часто используют конструкции **AEAD (Authenticated Encryption with Associated Data)**, например AES-GCM и ChaCha20-Poly1305.

---

# 9. Потоковые шифры

**Потоковый шифр** формирует псевдослучайную последовательность — **ключевой поток (keystream)** — которая комбинируется с данными, как правило, операцией XOR.

```text
Открытый текст ----\
                    XOR ----> Шифротекст
Ключевой поток ----/
```

Для расшифрования:

```text
Шифротекст -------\
                   XOR ----> Открытый текст
Ключевой поток ---/
```

Повторное использование одного ключевого потока для разных сообщений опасно и может разрушить конфиденциальность.

Исторический пример потокового шифра — RC4, который сегодня считается небезопасным. Современный пример — ChaCha20, часто применяемый вместе с Poly1305.

Нельзя утверждать, что блочные шифры всегда безопаснее потоковых или наоборот. Стойкость определяется конкретным алгоритмом, параметрами и корректностью применения.

| Характеристика | Блочные шифры | Потоковые шифры |
|---|---|---|
| Базовая обработка | Блоки фиксированной длины | Ключевой поток |
| Современный пример | AES | ChaCha20 |
| Критичный параметр | Режим, IV/nonce | Nonce и состояние потока |
| Пример AEAD | AES-GCM | ChaCha20-Poly1305 |

# 10. Асимметричная криптография

**Асимметричная криптография**, или криптография с открытым ключом, использует пару математически связанных ключей:

- **открытый ключ (public key)** — может распространяться открыто;
- **закрытый ключ (private key)** — должен храниться в секрете.

В зависимости от алгоритма ключевая пара применяется для шифрования, цифровой подписи или согласования общего секрета.

Важно не объединять все алгоритмы с открытым ключом в одну операцию. Например, Diffie–Hellman является механизмом согласования секрета, а ECDSA — алгоритмом цифровой подписи, а не шифрования.

Упрощённая схема шифрования для получателя:

```text
Алиса публикует PK_A
и хранит SK_A

Боб:
сообщение -> шифрование с PK_A -> шифротекст

Алиса:
шифротекст -> расшифрование с SK_A -> сообщение
```

Безопасность строится на вычислительной трудности восстановления закрытого ключа из открытого при корректных параметрах.

# 11. RSA

**RSA** — одна из наиболее известных криптосистем с открытым ключом.

Её стойкость связана с вычислительной трудностью факторизации больших целых чисел при корректном выборе параметров.

В учебных примерах RSA часто представляют как непосредственное шифрование сообщения открытым ключом. В реальных системах RSA требует безопасных схем дополнения и не должен применяться «в чистом виде».

Для шифрования применялись конструкции вроде RSA-OAEP, а для цифровой подписи — RSA-PSS.

---

# 12. Обмен ключами Диффи — Хеллмана

**Diffie–Hellman** — метод, позволяющий двум сторонам выработать общий секрет через открытый канал.

```text
Алиса                      Боб
  |                         |
секрет a                 секрет b
  |                         |
публичное A ------------>   |
  |   <------------ публичное B
  |                         |
вычисляет K              вычисляет K
  |                         |
  +------ общий секрет -----+
```

Общий секрет непосредственно по сети не передаётся.

Классический Diffie–Hellman сам по себе не аутентифицирует стороны. Если злоумышленник активно подменяет сообщения, возможна атака «человек посередине». Поэтому в реальных протоколах обмен ключами связывается с аутентификацией, сертификатами и подписями.

Современные варианты часто используют эллиптические кривые — ECDH или эфемерный ECDHE.

---

# 13. Эллиптические кривые

**Криптография на эллиптических кривых (ECC)** использует математические свойства групп точек эллиптических кривых над конечными полями.

Её практическое преимущество заключается в возможности достигать высокого уровня стойкости при относительно небольших размерах ключей.

На эллиптических кривых строятся разные схемы:

- ECDH — согласование общего секрета;
- ECDSA — цифровая подпись;
- EdDSA — семейство современных алгоритмов подписи.

ECC — не один конкретный алгоритм шифрования, а математическая основа для множества криптографических схем.

---

# 14. Цифровая подпись

**Цифровая подпись** — криптографический механизм, позволяющий проверить целостность сообщения и подтвердить, что подпись сформирована с использованием определённого закрытого ключа.

Упрощённо:

```text
Документ
   |
   v
Хеш-функция
   |
   v
Хеш документа
   |
   | закрытый ключ
   v
Подпись
```

При проверке применяется открытый ключ владельца подписи.

На практике подписывается не весь большой документ напрямую, а его хеш либо специальным образом сформированное представление.

Цифровая подпись не обеспечивает конфиденциальность документа. Подписанный файл может оставаться открытым для чтения.

Примеры алгоритмов подписи:

- RSA-PSS;
- ECDSA;
- EdDSA;
- ГОСТ Р 34.10-2012.

---

# 15. Гибридная криптография

Симметричные алгоритмы эффективны для больших объёмов данных, но требуют общего секрета. Асимметричные методы удобны для согласования ключей и аутентификации, но обычно требуют больше вычислительных ресурсов.

Поэтому современные протоколы используют **гибридный подход**:

```text
1. Стороны выполняют аутентифицированный обмен ключевым материалом.
2. Получают общий сеансовый секрет.
3. Из него выводятся симметричные ключи.
4. Основной поток данных защищается быстрым симметричным алгоритмом.
```

Так построены многие защищённые протоколы, включая TLS.

Современный TLS нельзя сводить к формуле «браузер шифрует общий ключ RSA-ключом сервера». В актуальных схемах часто применяется эфемерное согласование ключей, например ECDHE, что позволяет обеспечить **прямую секретность (forward secrecy)**.

---

# 16. Что такое хеш-функция

**Хеш-функция** — функция, преобразующая входные данные произвольной длины в значение фиксированной длины.

```text
Сообщение произвольной длины
              |
              v
         Хеш-функция
              |
              v
       Хеш фиксированной длины
```

Хеш также называют **дайджестом** или **хеш-значением**.

SHA-256 всегда формирует результат длиной 256 бит независимо от размера входных данных.

Пример:

```text
SHA-256("Hello, World!")
= dffd6021bb2bd7b0af676290809ec3a53191dd81c7f70a4b28688a362182986f
```

Если изменить один символ:

```text
SHA-256("Hello, world!")
= 315f5bdb76d078c43b8ac0064e4a0164612b1fce77c869345bfc94c75894edd3
```

результат меняется практически полностью.


# 17. Обычные и криптографические хеш-функции

Хеширование применяется не только в криптографии. Некриптографические хеш-функции используются в хеш-таблицах, индексах, дедупликации данных и других задачах, где важны скорость и равномерное распределение значений, но не требуется противодействие активному злоумышленнику.

**Криптографическая хеш-функция** проектируется с учётом дополнительных свойств стойкости. К ключевым относятся:

1. стойкость к поиску прообраза;
2. стойкость ко второму прообразу;
3. стойкость к коллизиям.

Также важен лавинный эффект: небольшое изменение входных данных должно приводить к существенному изменению результата.

## 17.1. Детерминированность

Хеш-функция является детерминированной:

```text
H(x) = H(x)
```

Если входные данные полностью совпадают, результат также совпадает.

Это свойство позволяет использовать хеши для проверки целостности.

## 17.2. Лавинный эффект

Хорошая криптографическая хеш-функция должна обладать **лавинным эффектом**: изменение одного бита во входных данных должно непредсказуемо менять значительную часть выходных битов.

Например:

```text
message
Message
```

отличаются только регистром первой буквы, но их SHA-256-хеши будут совершенно разными.

Это не означает, что результат действительно случаен. Хеш вычисляется строго детерминированно, но должен статистически вести себя подобно случайному отображению.

---

# 18. Стойкость к поиску прообраза

Пусть известно:

```text
y = H(x)
```

**Стойкость к поиску прообраза (preimage resistance)** означает, что по известному хешу `y` должно быть вычислительно трудно найти такое значение `x`, для которого:

```text
H(x) = y
```

Для идеализированной `n`-битной хеш-функции полный поиск требует порядка:

```text
2^n
```

операций.

При этом некорректно говорить, что восстановление исходных данных «математически невозможно». Если пространство исходных вариантов мало, например пользователь выбрал пароль `123456`, злоумышленник может перебрать вероятные кандидаты и сравнивать их хеши.

Именно поэтому криптографическая стойкость функции не компенсирует низкую энтропию входных данных.

---

# 19. Стойкость ко второму прообразу

Пусть известны сообщение `x` и его хеш:

```text
H(x)
```

**Стойкость ко второму прообразу (second preimage resistance)** означает, что должно быть вычислительно трудно найти другое сообщение `x'`, для которого:

```text
x' != x
H(x') = H(x)
```

Это свойство важно при защите документов и цифровых подписей. Если злоумышленник мог бы легко подобрать другое содержимое с тем же хешем, он мог бы попытаться заменить исходный документ без изменения контрольного значения.

---

# 20. Коллизии

**Коллизия** — ситуация, когда два различных входных сообщения имеют одинаковый хеш:

```text
x != x'
H(x) = H(x')
```

Коллизии математически неизбежны. Количество возможных входных сообщений не ограничено, а число возможных `n`-битных хешей равно `2^n`.

Поэтому криптографическая функция не обязана не иметь коллизий. Она должна делать их практический поиск вычислительно непосильным.

Для идеальной `n`-битной функции общий поиск коллизии требует порядка:

```text
2^(n/2)
```

операций.

Причина связана с **парадоксом дней рождения**.

Для SHA-256:

```text
поиск прообраза:            примерно 2^256 операций
поиск произвольной коллизии: примерно 2^128 операций
```

Эти оценки принципиально различаются, и смешивать их нельзя.

---

# 21. Популярные криптографические хеш-функции

## 21.1. MD5

MD5 формирует 128-битный хеш:

```text
128 бит = 16 байт = 32 шестнадцатеричных символа
```

MD5 больше не считается криптографически стойким, поскольку для него существуют практические методы построения коллизий.

Он не должен использоваться в новых системах для цифровых подписей, сертификатов и других задач, в которых злоумышленник может специально подбирать данные.

Иногда MD5 всё ещё встречается как простая контрольная сумма для обнаружения случайного повреждения, но для новых решений предпочтительны современные алгоритмы.

## 21.2. SHA-1

SHA-1 формирует 160-битный результат.

Для SHA-1 также продемонстрированы практические коллизионные атаки. Поэтому его не следует выбирать для новых криптографических систем, где требуется стойкость к коллизиям.

Историческое использование SHA-1 в системах контроля версий и старых протоколах не является основанием считать его современным алгоритмом защиты.

## 21.3. SHA-2

SHA-2 — семейство криптографических хеш-функций, включающее SHA-224, SHA-256, SHA-384 и SHA-512.

Наиболее часто встречается SHA-256:

```text
256 бит = 32 байта = 64 шестнадцатеричных символа
```

SHA-512 формирует:

```text
512 бит = 64 байта = 128 шестнадцатеричных символов
```

SHA-2 применяется для контроля целостности, цифровых подписей, HMAC и множества других криптографических задач.

## 21.4. SHA-3

SHA-3 — отдельное семейство криптографических хеш-функций, основанное на конструкции Keccak.

SHA-3 не является «исправленной версией SHA-2». Это альтернативная внутренняя конструкция.

К семейству относятся:

```text
SHA3-224
SHA3-256
SHA3-384
SHA3-512
```

Кроме того, семейство Keccak связано с расширяемыми функциями SHAKE.

## 21.5. ГОСТ Р 34.11-2012

ГОСТ Р 34.11-2012 определяет российскую криптографическую хеш-функцию, известную как «Стрибог».

Она поддерживает результаты длиной:

```text
256 бит
512 бит
```

Алгоритм используется в отечественных криптографических системах и связан с другими стандартами электронной подписи и защиты информации.

---

# 22. Хеш-функция не является шифрованием

Распространённая ошибка — говорить:

```text
пароль зашифрован SHA-256
```

Это неверно.

SHA-256 не шифрует данные. У него нет операции расшифрования и секретного ключа.

Корректные формулировки:

```text
вычислен SHA-256-хеш
```

или:

```text
получен дайджест сообщения
```

Принципиальное различие:

```text
шифрование -> исходные данные предполагается восстановить при наличии ключа
хеширование -> обратное восстановление не является предусмотренной операцией
```

---

# 23. Проверка целостности файлов

Один из самых понятных способов применения хеш-функции — контроль целостности файла.

Предположим, разработчик публикует образ операционной системы и рядом указывает SHA-256:

```text
installer.iso
SHA-256: 8c1f...
```

Пользователь скачивает файл и вычисляет хеш локально.

Если значения совпали, можно сделать вывод, что скачанный файл побитово совпадает с тем файлом, для которого был опубликован данный хеш.

Однако остаётся другой вопрос: можно ли доверять самому опубликованному значению?

Если злоумышленник получил возможность заменить одновременно файл и хеш на веб-сайте, простая проверка не обнаружит подмену. Поэтому для подтверждения происхождения применяются цифровые подписи, подписанные контрольные суммы и доверенные каналы публикации.

---

# 24. Хеширование паролей

Пароль в правильно спроектированной информационной системе не должен храниться в базе данных в открытом виде.

Упрощённая схема:

```text
Регистрация:
пароль -> функция хеширования паролей -> сохранённое значение

Вход:
введённый пароль -> та же функция -> сравнение
```

Если база данных будет скомпрометирована, злоумышленник не должен сразу получить исходные пароли.

Однако использовать для хранения паролей обычный SHA-256 недостаточно.

---

# 25. Почему SHA-256 недостаточно для хранения паролей

SHA-256 спроектирован быстрым. Для проверки целостности это полезное свойство.

Для паролей высокая скорость становится проблемой.

Получив базу хешей, злоумышленник может очень быстро проверять множество вариантов:

```text
123456
password
qwerty
admin123
...
```

Поэтому для паролей применяют специальные **password hashing functions** или функции выработки ключа, которые намеренно требуют заметных вычислительных ресурсов.

Примеры:

- Argon2id;
- scrypt;
- bcrypt;
- PBKDF2.

Их задача состоит не только в одностороннем преобразовании, но и в повышении стоимости массового перебора.

---

# 26. Соль

**Соль (salt)** — случайное значение, создаваемое отдельно для каждого пароля и включаемое в вычисление его сохранённого представления.

```text
пароль + уникальная соль
          |
          v
password hashing function
          |
          v
      результат
```

Соль не обязана быть секретной. Обычно она хранится рядом с хешем.

Её задача — сделать так, чтобы одинаковые пароли разных пользователей не приводили к одинаковым сохранённым значениям.

Например:

```text
Пользователь A:
пароль = qwerty
salt   = 81f0...

Пользователь B:
пароль = qwerty
salt   = e3a2...
```

Результаты будут различаться.

Соль также резко снижает практическую эффективность заранее вычисленных таблиц соответствий.

---

# 27. Pepper

Дополнительно некоторые системы используют **pepper** — секретное значение, общее для системы и хранящееся отдельно от базы паролей.

```text
пароль + salt + pepper
```

В отличие от соли, pepper должен оставаться секретным.

Это дополнительный защитный механизм, но он не заменяет специализированную функцию хеширования паролей.

---

# 28. Полный перебор и словарная атака

## 28.1. Полный перебор

**Brute force** — последовательная проверка вариантов из некоторого пространства.

Если пароль состоит только из четырёх десятичных цифр, число вариантов равно:

```text
10^4 = 10000
```

Для современного компьютера такое пространство чрезвычайно мало.

## 28.2. Словарная атака

Пользователи часто выбирают не случайные строки, а слова, даты, имена и типичные шаблоны.

Поэтому злоумышленник может проверять наиболее вероятные варианты:

```text
password
qwerty123
admin
letmein
12345678
```

Словарный подход часто значительно эффективнее полного перебора.

## 28.3. Почему соль не делает слабый пароль сильным

Соль предотвращает эффективное повторное использование заранее подготовленных таблиц и отделяет одинаковые пароли разных пользователей.

Но если пароль слабый, злоумышленник всё равно может перебирать кандидаты для конкретной записи.

Поэтому защита паролей строится одновременно на нескольких мерах:

- стойкий и уникальный пароль;
- уникальная соль;
- медленная специализированная функция;
- корректные параметры вычислительной стоимости;
- защита базы данных;
- многофакторная аутентификация.

---

# 29. Радужные таблицы

**Rainbow table** — предварительно вычисленная структура, позволяющая искать соответствия между хешами и вероятными исходными значениями с компромиссом между объёмом хранения и временем поиска.

Такие атаки особенно полезны против большого числа паролей, хешированных одинаковым быстрым алгоритмом без уникальной соли.

Соль делает одну общую заранее вычисленную таблицу существенно менее полезной, поскольку для каждого значения соли требуется учитывать другое отображение.

---

# 30. Атака дней рождения

Парадокс дней рождения показывает, что совпадение двух значений появляется значительно раньше, чем интуитивно кажется.

Для `n`-битной хеш-функции поиск любой пары сообщений с одинаковым хешем имеет порядок:

```text
2^(n/2)
```

Это не то же самое, что поиск сообщения для заранее известного хеша.

Для SHA-256:

```text
поиск прообраза: ~ 2^256
поиск коллизии:  ~ 2^128
```

---

# 31. HMAC

Обычный хеш не содержит секрета.

Если Алиса передаёт:

```text
сообщение + SHA-256(сообщение)
```

злоумышленник, способный изменить сообщение, может вычислить и новый SHA-256.

Для проверки целостности и аутентичности сообщения при наличии общего секретного ключа применяется **HMAC (Hash-based Message Authentication Code)**.

Упрощённо:

```text
HMAC(secret_key, message) -> tag
```

Получатель, владеющий тем же секретным ключом, повторно вычисляет HMAC и сравнивает результат.

HMAC обеспечивает:

- контроль целостности;
- подтверждение владения общим секретом.

При этом HMAC не шифрует сообщение и не обеспечивает его конфиденциальность.

---

# 32. Proof of Work и хеширование

Хеш-функции применяются и в системах доказательства выполнения вычислительной работы.

Упрощённая задача может выглядеть так:

```text
H(данные || nonce) < target
```

Участник меняет `nonce` и многократно вычисляет хеш, пока результат не удовлетворит заданному условию.

В популярных объяснениях это часто представляют как поиск хеша, начинающегося с определённого количества нулей.

Важно понимать, что Proof of Work не является хеш-функцией. Это механизм, использующий вычислительную стоимость многократного хеширования.

# 33. Генерация ключей и случайность

Криптографический алгоритм может быть математически стойким, но система останется уязвимой, если ключи предсказуемы.

Для создания ключей, nonce и токенов нужен **криптографически стойкий генератор случайных чисел**.

В Python для этого предназначен модуль:

```python
import secrets
```

Например:

```python
import secrets

key = secrets.token_bytes(32)
print(key.hex())
```

Этот код создаёт 32 случайных байта, то есть 256 бит ключевого материала.

Модуль `random` предназначен прежде всего для моделирования и статистических задач и не должен использоваться для создания криптографических секретов.

# 34. Управление ключами

На практике безопасность определяется не только выбором алгоритма.

Необходимо защищать полный жизненный цикл ключа:

```text
генерация
   ↓
хранение
   ↓
распространение
   ↓
использование
   ↓
ротация
   ↓
отзыв
   ↓
уничтожение
```

Например, AES-256 не обеспечит конфиденциальность, если 256-битный ключ хранится открыто рядом с зашифрованным файлом.

Ключи могут храниться в защищённых хранилищах секретов, HSM, TPM, специализированных системах управления ключами и других защищённых средствах.

**Управление ключами** является одной из наиболее сложных практических задач применения криптографии.

# 35. Типовые ошибки при использовании криптографии

Даже надёжный алгоритм можно применить неправильно.

К распространённым ошибкам относятся использование устаревших алгоритмов, выбор режима ECB, повтор nonce или IV там, где требуется уникальность, отсутствие контроля целостности шифротекста и хранение секретов непосредственно в исходном коде.

Опасной практикой является и самостоятельное конструирование криптографического протокола по принципу «возьмём AES, SHA-256 и RSA и соединим их». Наличие нескольких надёжных примитивов не гарантирует безопасность всей схемы.

Отдельно следует выделить следующие ошибки:

**Использование одного SHA-256 для паролей.** Быстрая функция позволяет эффективно перебирать варианты.

**Слабая случайность.** Предсказуемый ключ делает стойкий шифр бесполезным.

**Повтор nonce в GCM или потоковом шифре.** В ряде схем это может привести к серьёзной компрометации.

**Хранение закрытого ключа в Git-репозитории.** Секрет, однажды опубликованный, следует считать скомпрометированным даже после удаления из последней версии проекта.

---

# 36. Почему не следует создавать собственный шифр

Самодельная схема может внешне выглядеть сложной:

```text
XOR
+ перестановка
+ несколько хешей
+ Base64
+ случайное число
```

но сложность конструкции не означает криптографическую стойкость.

Криптографические алгоритмы проходят многолетний публичный анализ. Специалисты исследуют их математические свойства, возможность дифференциального и линейного криптоанализа, побочные каналы, ошибки реализации и множество других аспектов.

В прикладной разработке правильнее использовать:

1. общепринятый современный алгоритм;
2. стандартный безопасный режим;
3. проверенную криптографическую библиотеку;
4. безопасную генерацию ключей;
5. документированные правила управления nonce, IV и ключами.

    result = []

    for char in text:
        if "A" <= char <= "Z":
            base = ord("A")
            encrypted = chr((ord(char) - base + shift) % 26 + base)
            result.append(encrypted)
        elif "a" <= char <= "z":
            base = ord("a")
            encrypted = chr((ord(char) - base + shift) % 26 + base)
            result.append(encrypted)
        else:
            result.append(char)

    return "".join(result)


def caesar_decrypt(text: str, shift: int) -> str:

import hashlib
from pathlib import Path


def sha256_file(path: str) -> str:
    hasher = hashlib.sha256()

    with open(path, "rb") as file:
        for chunk in iter(lambda: file.read(8192), b""):
            hasher.update(chunk)

    return hasher.hexdigest()

# Вывод

В рамках занятия были рассмотрены основные понятия и направления современной криптографии. Показано, что криптографическая защита не сводится к одному шифрованию: для построения защищённых информационных систем совместно применяются симметричные алгоритмы, механизмы с открытым ключом, хеш-функции, цифровые подписи, коды аутентификации сообщений и криптографически стойкие генераторы случайных чисел.

Симметричное шифрование эффективно при обработке больших объёмов данных, однако требует безопасного распределения ключей. Асимметричная криптография позволяет решать задачи согласования секретов и цифровой подписи, но обычно используется совместно с симметричными алгоритмами в гибридных протоколах.

Криптографические хеш-функции обеспечивают компактное одностороннее представление данных и используются для контроля целостности, в цифровых подписях и множестве других механизмов. При этом обычные быстрые хеш-функции не являются правильным решением для хранения пользовательских паролей: для этой задачи применяются специализированные функции, такие как Argon2id, scrypt, bcrypt или PBKDF2, вместе с уникальной солью.

Главный практический вывод заключается в том, что безопасность криптографической системы определяется не только математической стойкостью выбранного алгоритма. Не менее важны режим его применения, генерация случайных значений, управление ключами, аутентификация сторон, безопасное хранение секретов и корректная реализация протокола в целом.
