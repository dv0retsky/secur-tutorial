# Практическое занятие №15: Оформление пояснительной записки и подготовка к защите

## 1. Проверка структуры пояснительной записки

Рекомендуемая структура:

```text
Титульный лист
Задание
Оглавление

Введение

1. Анализ предметной области
2. Анализ угроз и проектирование защиты
3. Программная реализация
4. Экспериментальная проверка

Заключение
Список использованных источников
Приложения
```

Названия подразделов могут отличаться, но должна сохраняться общая логика:

```text
анализ
→
угрозы
→
требования
→
защита
→
реализация
→
проверка
```

## 2. Введение

Во введении необходимо отразить:

- актуальность;
- объект исследования или разработки;
- предмет;
- цель;
- задачи.

Цель должна соответствовать фактически полученному результату.

Пример:

> Целью курсовой работы является разработка программного прототипа защищённой системы хранения пользовательских файлов, обеспечивающей конфиденциальность и контроль целостности данных.

## 3. Заключение

Заключение не должно повторять главы. Оно подводит итог всей работе.

Необходимо показать:

- что было разработано;
- какие методы защиты реализованы;
- какие результаты получены;
- подтвердило ли тестирование выполнение требований;
- какие ограничения остаются.

Пример логики:

```text
цель
→
реализованный результат
→
методы защиты
→
проверка
→
основные выводы
```

## 4. Оглавление и оформление структуры

Перед сдачей необходимо проверить:

- последовательность заголовков;
- нумерацию разделов;
- ссылки на рисунки;
- ссылки на таблицы;
- корректность оглавления;
- единообразие терминов;
- отсутствие незаполненных фрагментов.

Автоматическое оглавление предпочтительнее ручного.

## 5. Приложения

В приложения рекомендуется выносить материалы, которые слишком громоздки для основного текста:

- большие листинги;
- дополнительные таблицы;
- полный набор тест-кейсов;
- инструкции;
- дополнительные схемы;
- вспомогательные скриншоты.

Ключевые решения всё равно должны быть объяснены в основном тексте.

## 6. Презентация проекта

Презентация должна быть подготовлена в PDF.

Рекомендуемая структура:

1. Титульный слайд.
2. Актуальность и цель.
3. Описание защищаемой системы.
4. Основные угрозы.
5. Архитектура.
6. Реализованные методы защиты.
7. Результаты тестирования.
8. Итоговые результаты.
9. Спасибо за внимание.

Оптимальный объём — 7–10 содержательных слайдов.

## 7. Что не следует помещать на слайды

Не рекомендуется:

- копировать большие абзацы из отчёта;
- вставлять длинные листинги;
- использовать нечитаемые скриншоты;
- показывать только интерфейс;
- перегружать слайды мелким текстом.

Основная задача презентации — визуально поддержать доклад.

## 8. Подготовка демонстрации

Демонстрацию необходимо заранее проверить.

Рекомендуемый сценарий:

```text
1. Запуск приложения
2. Нормальная работа
3. Попытка нарушения требования
4. Срабатывание механизма защиты
5. Подтверждение результата
```

Тестовые данные и учётные записи должны быть подготовлены заранее.

## 9. Подготовка доклада

Доклад должен отвечать на вопросы:

```text
Что разработано?
Почему это нужно защищать?
Какие угрозы рассматривались?
Какие механизмы реализованы?
Как проверялась их работа?
Каков результат?
```

Не нужно подробно пересказывать исходный код. Важнее объяснить проектные решения.

## 10. Предзащита

На занятии проводится пробная защита.

Необходимо представить:

- презентацию;
- рабочий проект;
- краткий доклад;
- демонстрационный сценарий;
- практически готовую пояснительную записку.

По итогам предзащиты формируется перечень исправлений.

## 11. Что нужно сдать на этой учебной неделе

К концу недели должны быть подготовлены:

- полный черновик пояснительной записки;
- введение;
- заключение;
- список источников;
- приложения;
- итоговая версия репозитория;
- презентация в PDF;
- сценарий демонстрации;
- перечень исправлений после предзащиты.

## 12. Чек-лист перед финальной защитой

```text
[ ] цель соответствует результату
[ ] задачи отражены в тексте
[ ] модель угроз согласована с архитектурой
[ ] методы защиты обоснованы
[ ] тестирование представлено
[ ] иллюстрации подписаны
[ ] ссылки на источники присутствуют
[ ] README актуален
[ ] проект запускается
[ ] презентация готова
[ ] демонстрация отрепетирована
```
